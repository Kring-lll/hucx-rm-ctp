## Ownership boundary
URMA SDK/provider/driver/device provide RM mode, CTP selection, resource creation/import, registered memory, SEND/READ/WRITE posting and CQ polling. HUCX adapter selects URMA_TM_RM and URMA_CTP; this is not a reimplementation of hardware CTP. New RM UCT integration supplies UCX operations, endpoint/wireup state, software AM DATA/ACK framing, sequencing/duplicates/retransmission, progress and resource lifetime. UCP supplies upper MPI message protocols and fragmentation; distinguish these from native CTP wire packets. No credible percentage of 'our code vs URMA' without defined denominator/provenance audit. Existing UB common MD code also contains inherited code and new fixes.

## Confirmed application-side choices
Every nonzero rm_op_alloc allocates operation plus aligned buffer, zeros rounded4KiB units and invokes urma_register_seg. rm_send uses this for each DATA; rm_progress_acks uses it for each ACK too. rm_op_release invokes unregister and frees. These costs recur in steady state. RM AM short/bcopy stage into temporary storage and copy again; RC implementation has inline SEND call sites and pooled descriptors. Native rm_rma imports a remote segment per operation, releases it with operation lifetime, and serializes RMA vs AM. Potential bottlenecks do not establish quantified contribution.
