# MPI 中心多对端资源用例（待节点验收）

中心 rank0 固定 node89；其他1/2/4/8个 rank 放 node97。每个进程必须加载已自检的观测器。先跑1个对端，再逐级增加，不自动全量运行。

每条边进行64 B请求与回复，按对端编号生成数据并逐字节检查；中心逐个通信，避免并发压力混入第一轮资源规模实验。after_init、after_exchange、after_finalize及process_exit快照用于区分初始化、通信、销毁阶段。中心拍摄after_exchange时，各对端在等待中心放行，不提前Finalize。该快照之前没有显式MPI集合操作。MPI初始化/结束自身仍可能建立额外端点，需要按阶段识别。

这不是压力、带宽或时延测试，也不验证物理节点扩展；同一节点上的多个对端进程不等于多个物理节点。先保留当前可用配置，随后记录/控制RC与RM队列差异。RC辅助UM对象应单独归因。API对象数量不等于硬件TP数量和内存占用。程序不要求资源数量符合预期模型，避免将假设写成验收条件。

本地仅进行替代MPI头文件的严格编译检查，未链接真实MPI或在节点运行。build_star.sh使用节点已验收的MPI编译器生成独立测试程序，不改HUCX、HMPI或观测器。
